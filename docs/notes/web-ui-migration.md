# Pinky desktop UI → Wails + React (full replacement)

**Audience:** implementer AI / engineer on fork `tarou-jp/smartphone-agent` (`main` as of 2026-11-10, commit `277f327` and later).

**Decision:** Replace the entire MyGo desktop UI (`ui/`) with a **Wails** shell and a **React + TypeScript** front end (Vite; Next.js not required). **All Go below the UI stays:** `internal/gateway`, drivers, MCP, policy, `internal/inapp`, `cmd/pinky` daemon/MCP paths.

**Do not** change upstream `DIYgod/pinky` until the fork is stable. Read [WORKING.md](../WORKING.md) and [client.md](client.md) before editing.

---

## 1. Goals and non-goals

### Goals

- Cursor-class **in-app chat / composer** (queue, Steer, Stop, streaming, scroll) and room to match Cursor visuals with CSS.
- **Parity** with current MyGo client behaviour documented in [client.md](client.md): mirrors, approvals, Needs you, Activity, Settings, Add phone, menu bar, notifications, global Stop-all shortcut, background/hidden start.
- **One process** for the desktop app: gateway + UI (same as today’s `pinky` / default command).
- **Locales:** en, ja, zh-Hans (reuse strings from `cmd/pinky/locales/*.json` or migrate to `react-i18next` JSON derived from them).

### Non-goals (first release of web UI)

- Replacing **MyGo** in the **release pipeline** on day one (phased; see §6).
- Putting **API keys or PINs** in the front end or `localStorage` (all via Go + OS keychain).
- Changing **agent-facing** MCP semantics or `gateway.API` contract for external agents.
- Electron.

## 5. Go ↔ frontend contract

### 5.1 Wails bindings (sync RPC)

Use for short calls with clear JSON structs:

- `GetDevices()`, `GetTasks()`, `GetNeeds()`, `GetSettings()`, `SaveSettings(partial)`
- `Decide(needID, decision, note)`, `Unlock(deviceID)`, `TakeOver`, `HandBack`, `Stop`, `StopAll`
- `Touch`, `Key`, `Text` (mirror input)
- `RevealModelAPIKey(provider)` → Go only; never return key to logs
- `ChatSend(sessionID, text, deviceScope)`, `ChatStop()`, `ChatQueue*`
- `Quit()`, `OpenPath`, `ExportHistory`, etc.

**Subscriptions:** Prefer **Wails runtime events** (`runtime.EventsEmit` / `OnEvent`) for:

- `gateway.Event` stream (devices/tasks/needs changed) — mirror today’s `Subscribe`
- Toast messages, update available

### 5.2 Streaming (chat + agent progress)

- **Server-Sent Events** or **WebSocket** on loopback (e.g. `127.0.0.1:0` chosen by Go, URL passed to front end at startup).
- Events: `chat.token`, `chat.tool`, `chat.done`, `chat.error`, `chat.cancelled`.
- Must match behaviour in current `ui/chat.go` (single streaming bubble, queue flush, interrupt).

### 5.3 Mirror video (critical path — spike in Phase 0)

Today: `gateway.API.Stream` → FFmpeg decode → `mg.Bitmap` ([ui/mirror.go](../../ui/mirror.go)).

**Options (pick one in Phase 0 spike; document FPS/latency/CPU):**

| Option | Pros | Cons |
|--------|------|------|
| **A. JPEG/PNG frames over WS** | Simple | Bandwidth/CPU heavy at 60fps |
| **B. H.264 fMP4 or raw NAL over MSE** | Efficient | More JS plumbing |
| **C. Offscreen native child view** | Best perf | Breaks “all web UI” purity; platform-specific |
| **D. Canvas + RGBA shm from Go** | Medium complexity | Wails custom asset / shared buffer APIs |

**Acceptance for mirror:** Same perceived latency as MyGo on one iPhone + one Android fake; touch mapping correct; agent overlay (target box) if kept in MVP.

### 5.4 Secrets

- All `secret.Store` / Touch ID / Windows Hello flows stay in Go.
- Front end receives **boolean** `hasAnthropicKey`, not the key.
- Same session cache semantics as `ui/model.go` `revealModelAPIKey` (optional).

## 6. Migration strategy (phased, not big-bang)

Do **not** delete `ui/` until **parity checklist** (§8) passes on fake API and one real device.

| Phase | Deliverable | MyGo `ui/` |
|-------|-------------|------------|
| **0 — Spike (1–2 weeks)** | Wails window + React shell; `deskapi` hello; **mirror spike** report; SSE chat prototype | Unchanged; `go run ./cmd/pinky` still default |
| **1 — Shell + phones list** | Sidebar, device status, routing; `Subscribe` events; quit/hidden | Still used for mirror until Phase 2 |
| **2 — Mirror + input** | Full phone page in web; takeover banner; basic keys | MyGo mirror off for dev flag |
| **3 — Needs + approvals** | Right panel + approval floating window equivalent | |
| **4 — Activity + Settings** | History, export, settings sections, model keys UI | |
| **5 — Add phone + checkups** | Pairing flows calling existing Go helpers | |
| **6 — Menu bar, shortcuts, notifications** | macOS tray, global shortcut, system notifications | |
| **7 — Cutover** | `cmd/pinky` default = Wails; remove MyGo from `go.mod` UI path | Delete `ui/*.go` except extracted pure helpers |
| **8 — CI / release** | Replace `mygo build` UI assumptions; e2e with Playwright or Wails test harness | |

**Feature flag:** `-ui=web` or build tag `webui` until Phase 7. Example: `go run ./cmd/pinky -ui=web`.

## 8. Parity checklist (release gate)

Minimum before removing MyGo UI:

- [ ] Fake API demo: all `pinky-ui-demo` scenarios runnable against web UI (`ui/fakeapi` + `deskapi`).
- [ ] Live gateway: one Android + one iPhone — mirror, approve, stop, takeover, hand back.
- [ ] Menu bar / tray: open window, show need count; hidden start opens on first need.
- [ ] Global Stop-all shortcut.
- [ ] Settings persist; rules file hand-edit refresh.
- [ ] Unlock with saved PIN (platform keychain).
- [ ] In-app agent: tool loop, queue, steer, Ollama + cloud fallback.
- [ ] Locales: ja + en smoke-tested.
- [ ] `make check` passes; new frontend `pnpm lint && pnpm build` in CI.
- [ ] No regression: `pinky daemon`, `pinky mcp` unchanged.

## 10. Build and release impact

- **Dev:** `wails dev` (Go + Vite HMR).
- **Prod:** `wails build` embeds `frontend/dist`; still one `pinky` binary (plus platform packaging).
- **Upstream** uses `go tool mygo build` ([Makefile](../../Makefile), [docs/RELEASING.md](../RELEASING.md)). Fork must document divergence until upstream adopts Wails or maintains dual UI.

**FFmpeg / companion APK / signing:** unchanged; only the window toolkit changes.

## 11. Risks and mitigations

| Risk | Mitigation |
|------|------------|
| Mirror performance | Phase 0 spike; fallback hybrid native viewer only for video if needed |
| Wails + macOS notarization | Follow Wails docs; early test signed build |
| 6+ months dual UI maintenance | Strict phases; feature flag; delete MyGo at Phase 7 |
| i18n drift | Script: locales JSON → frontend JSON |
| Accessibility | Wails uses system webview; test VoiceOver basics on approvals |
